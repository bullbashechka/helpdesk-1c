# PRD — Информационная система учёта заявок клиентов (Service Desk)

## О продукте

Веб-приложение для компании-франчайзи 1С, предназначенное для учёта обращений клиентов: консультаций, доработок, ошибок и обновлений. Система заменяет разрозненную регистрацию заявок (телефон, почта, мессенджеры) единым рабочим местом, где менеджер фиксирует заявки, назначает исполнителей, отслеживает статусы и сроки, ведёт историю выполненных работ и формирует отчёты.

Система рассчитана на одного пользователя (менеджера/диспетчера), работающего за одним рабочим местом. Авторизация и разделение прав не предусмотрены.

## Технологический стек

- Frontend: React + Vite
- Backend: Node.js + Express, REST API, обмен данными в формате JSON
- База данных: SQLite, доступ через библиотеку `better-sqlite3`
- Архитектура: трёхслойная клиент-серверная (React → REST API → SQLite). Внешние ключи в SQLite включаются принудительно (`PRAGMA foreign_keys = ON`).

## Структура базы данных

База данных состоит из семи таблиц.

**Клиенты** — наименование организации, БИН/ИИН, контактное лицо, телефон, email, адрес.

**Договоры** — ссылка на клиента, номер договора, дата начала, дата окончания, тип сопровождения, тариф.

**Сотрудники** — ФИО, должность, телефон, email.

**Заявки** — ссылка на договор, ссылка на категорию, ссылка на статус, ссылка на ответственного сотрудника, тема, описание, приоритет, дата создания, дедлайн.

**Статусы** — справочник состояний заявки (новая, в работе, ожидает клиента, выполнена, закрыта).

**Категории заявок** — справочник типов заявки (консультация, доработка, ошибка, обновление).

**Работы по заявке** — ссылка на заявку, ссылка на сотрудника, дата, описание выполненной работы, количество затраченных часов.

Связи: один клиент имеет много договоров; один договор содержит много заявок; одна заявка имеет одного ответственного сотрудника; одна заявка содержит много записей о работах; одна запись о работе относится к одному сотруднику. Связь «многие-ко-многим» между заявками и сотрудниками реализуется через таблицу работ.

Удаление клиентов, договоров, сотрудников и заявок запрещено, если на запись ссылаются связанные данные. В этом случае система показывает пользователю понятное сообщение о причине отказа.

## Функциональность

### Дашборд

Стартовый экран приложения. Показывает сводку по текущему состоянию заявок, чтобы пользователь сразу видел общую картину без перехода в списки.

Содержит счётчики: общее количество заявок, количество заявок в каждом статусе, количество просроченных заявок. Содержит как минимум два графика: распределение заявок по статусам и распределение заявок по категориям. Ниже сводки выводится список последних заявок.

### Список заявок

Основной рабочий экран. Отображает заявки в виде таблицы со столбцами: тема, клиент, категория, статус, приоритет, дата создания, дедлайн, исполнитель.

В списке предусмотрена подсветка просроченных заявок — строки, у которых дедлайн прошёл, а заявка не закрыта, визуально выделяются. Доступен фильтр «просроченные», показывающий только такие заявки.

Над списком расположена строка простого поиска: пользователь вводит текст, система ищет совпадения по теме и описанию заявок.

Из списка можно открыть карточку любой заявки и перейти к созданию новой.

### Создание и редактирование заявки

Форма для регистрации новой заявки и изменения существующей. Пользователь заполняет: договор (с выбором клиента), категорию, статус, ответственного сотрудника, тему, описание, приоритет, дедлайн. Дата создания проставляется автоматически при сохранении новой заявки.

При создании заявки обязательны договор, категория, статус, ответственный сотрудник, тема и приоритет. Описание и дедлайн можно оставить пустыми.

Те же поля доступны для редактирования существующей заявки, включая смену статуса по мере выполнения работ.

### Карточка заявки и история работ

Экран детального просмотра одной заявки. Показывает все данные заявки: клиента и договор, категорию, статус, ответственного сотрудника, приоритет, тему, описание, дату создания, дедлайн.

В карточке ведётся история работ — список всех записей о выполненных действиях по этой заявке. Каждая запись содержит исполнителя, дату, описание выполненной работы и количество затраченных часов. Пользователь может добавить новую запись о работе прямо из карточки.

### Справочник клиентов

Экран управления клиентами. Показывает список всех клиентов и позволяет добавлять, редактировать и удалять записи. Поля клиента: наименование, БИН/ИИН, контактное лицо, телефон, email, адрес.

### Справочник договоров

Экран управления договорами. Показывает список договоров и позволяет добавлять, редактировать и удалять записи. Каждый договор привязан к клиенту. Поля договора: клиент, номер, дата начала, дата окончания, тип сопровождения, тариф.

### Справочник сотрудников

Экран управления сотрудниками. Показывает список сотрудников и позволяет добавлять, редактировать и удалять записи. Поля сотрудника: ФИО, должность, телефон, email.

### Статусы и категории

Статусы заявок (новая, в работе, ожидает клиента, выполнена, закрыта) и категории заявок (консультация, доработка, ошибка, обновление) являются фиксированными справочниками. Их значения заданы в системе заранее и не редактируются пользователем через интерфейс. Заявки ссылаются на эти справочники при создании и редактировании.

Статус «выполнена» означает, что работы по заявке завершены исполнителем. Статус «закрыта» означает, что завершение подтверждено менеджером или клиентом, и заявка больше не требует действий. Просроченными считаются заявки с прошедшим дедлайном во всех статусах, кроме «закрыта».

### Отчёты и экспорт

Раздел формирования отчётов. Предусмотрено два отчёта:

Отчёт «Заявки за период» — пользователь задаёт диапазон дат, система показывает заявки, созданные в этом периоде, с основными данными.

Отчёт «Часы по сотрудникам» — система показывает суммарное количество затраченных часов по каждому сотруднику на основе записей о работах, с возможностью ограничения периодом.

Любой сформированный отчёт можно выгрузить в файл формата CSV для дальнейшей обработки.

### Демонстрационные данные

При первом запуске база данных наполняется демонстрационными данными: несколько клиентов, договоров, сотрудников и заявок с записями о работах, а также заранее заданные значения справочников статусов и категорий. Это позволяет сразу увидеть работу всех экранов, списков, графиков и отчётов без ручного ввода.
