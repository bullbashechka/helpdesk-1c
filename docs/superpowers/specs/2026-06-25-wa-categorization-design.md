> `problem`, код «Прочего» — `other`. Стем в конфигурации теперь `@гем`.
> Описанный ниже механизм распознавания (нижний регистр, разбивка на слова,

> иллюстрация работы стем-поиска.

## Контекст и цель

Входящие WhatsApp-сообщения попадают в инбокс сплошным потоком без сортировки — оператор вручную разбирает всё подряд. Нужно автоматически отделять обращения-заявки от остального потока. Клиентов приучаем помечать обращение упоминанием «@ГЕМ»; система распознаёт пометку и относит такие сообщения к категории «ГЕМ», остальные — к категории «Прочее». Оператор получает возможность фильтровать инбокс по категории и быстро добираться до заявок.

Категория описывает **содержание** сообщения и существует независимо от статуса обработки (новое / в работе / задача / архив). Автоопределение категории — это подсказка: финальное решение всегда за оператором, он может переназначить категорию вручную.

---

## Фича 1. Категория сообщения как новое свойство

У каждого WhatsApp-сообщения появляется категория. В MVP их две:

- **«ГЕМ»** — сообщение содержит пометку обращения (упоминание «@ГЕМ», распознаётся автоматически).
- **«Прочее»** — всё остальное; это категория по умолчанию.

Категория проставляется каждому сообщению — и новым, и демонстрационным. Сообщения без текста (только вложение, например фото или голосовое) относятся к «Прочему».

Категория не влияет на статус обработки и не меняет его: сообщение «Прочее» остаётся в инбоксе наравне с заявками, ничего не скрывается и не архивируется автоматически. Разница только в пометке и в возможности отфильтровать поток.

Дополнительно у сообщения хранится признак того, как была определена категория: автоматически системой или вручную оператором. Это нужно, чтобы ручное решение оператора считалось окончательным и не выглядело как автоподсказка.

Категория сообщения — самостоятельная сущность WhatsApp-инбокса и **не связана** с уже существующими категориями тикетов (Консультация/Доработка/Ошибка и т. д. в таблице `categories`). Чтобы не путать два смысла слова «категория», поля сообщения именуются отдельно (категория сообщения и источник её определения хранятся прямо в записи сообщения, а не ссылкой на справочник тикетов).

## Фича 2. Автоматическое распознавание на приёме сообщений

При получении нового сообщения система анализирует его текст и определяет категорию.

Распознавание работает так:

- Регистр не важен: «Проблема», «ПРОБЛЕМА», «проблема» распознаются одинаково (весь текст приводится к нижнему регистру перед сравнением).
- Текст разбивается на слова по пробельным символам (пробел, перенос строки, таб). Знаки препинания и кавычки вокруг слова не снимаются: «"проблема"», «(проблема)» — не распознаются как заявка (компромисс: оператор поправит вручную).
- Хвост слова не мешает: «проблема!!!», «проблема,» — распознаются, потому что сравнение идёт по началу слова (startsWith), а не по точному совпадению.
- Хэштег учитывается: перед сравнением у каждого слова снимаются **все** ведущие `#` — «#проблема» и «##проблема» распознаются одинаково.
- Распознаются все падежи и формы за счёт поиска по основе (стему) слова: достаточно, чтобы слово в сообщении начиналось со стема «проблем» — это покрывает «проблема», «проблемы», «проблему», «проблемой», «проблеме», «проблем» и хэштег-формы.
- Сравнение идёт по отдельным словам сообщения, а не по случайному вхождению букв внутри других слов: «беспроблемный» не распознаётся (начинается с «бес»).
- Защита от пустого стема в конфиге: при загрузке конфига стемы нормализуются (нижний регистр + trim), пустые строки отбрасываются — случайный пустой стем не «матчит» все слова подряд.

Если хотя бы одно слово сообщения совпало по стему с категорией — сообщению присваивается эта категория, источник определения — «автоматически». Если совпадений нет — категория «Прочее».

Возможные «пограничные» срабатывания (например, слово «проблематично») система тоже отнесёт к «Проблеме». Это осознанный компромисс: автоопределение — лишь подсказка, и оператор всегда может переназначить категорию вручную.

Определённая категория сохраняется в записи сообщения при приёме — она не вычисляется заново при каждом показе. Но если конфигурация ключевых слов меняется (добавлено слово или новая категория), при следующем старте приложения авто-категория **пересчитывается** для всех сообщений с источником «автоматически», чтобы инбокс соответствовал актуальной конфигурации. Сообщения с источником «вручную» при пересчёте не трогаются — ручное решение оператора остаётся окончательным.

## Фича 3. Ключевые слова и категории вынесены в конфигурацию

Список категорий и относящихся к ним ключевых слов (стемов) хранится в отдельном конфигурационном файле, отдельно от логики обработки. Каждая категория описывается своим набором стемов.

Добавление новой категории или нового ключевого слова к существующей категории выполняется правкой только этого конфигурационного файла — без изменения кода распознавания, API или интерфейса. Категория «Прочее» — служебная категория по умолчанию, ключевых слов у неё нет: в неё попадает всё, что не подошло ни под одну другую категорию.

Если по тексту подходит несколько категорий, применяется первая подходящая по порядку их перечисления в конфигурации.

В MVP у категории «ГЕМ» один ключевой стем — «@гем». Синонимы (ошибка, сбой и т. п.) намеренно не добавляются: цель — приучить клиентов помечать обращение упоминанием «@ГЕМ», а не ловить максимум формулировок. При необходимости список расширяется правкой конфигурации (стемы однословные — фразовые ключи вроде «не работает» механизмом поиска по стему не поддерживаются).

## Фича 4. Фильтр по категории и счётчики в API

API списка сообщений и сводки расширяется категорией:

- Список сообщений можно запросить с фильтром по категории («ГЕМ» или «Прочее»). Фильтр по категории комбинируется с уже существующим фильтром по статусу обработки — например, можно получить только новые сообщения категории «ГЕМ».
- Каждое сообщение в выдаче содержит свою категорию и признак источника определения (авто/вручную).
- Сводка по сообщениям дополняется счётчиками по категориям: количество сообщений «ГЕМ», «Прочее» и общее число. Счётчики приходят вместе с уже существующими счётчиками по статусам.

Некорректное значение категории в запросе фильтра не приводит к ошибке — оно просто игнорируется (показываются все категории), по аналогии с обработкой статуса.

## Фича 5. Ручное переназначение категории оператором

Оператор может вручную сменить категорию любого сообщения. Для этого в API добавляется отдельное действие переназначения категории по идентификатору сообщения.

При ручной смене:

- Новая категория проверяется на допустимость по конфигурации; недопустимое значение отклоняется понятным сообщением об ошибке на русском языке.
- Источник определения категории помечается как «вручную» — это фиксирует решение оператора как окончательное.
- Переназначение доступно независимо от статуса обработки сообщения.

Автоопределение остаётся подсказкой и никогда не перекрывает ручное решение оператора.

---

## Фича 6. Фильтр и бейдж категории в инбоксе (фронтенд)

В разделе «Вопросы с WhatsApp» над существующими вкладками статусов появляется отдельный ряд фильтра по категории: «Все», «ГЕМ», «Прочее» — каждая вкладка со своим счётчиком. Фильтр по категории работает совместно с фильтром по статусу: оператор может, например, выбрать одновременно «Новое» по статусу и «ГЕМ» по категории.

На карточке сообщения в таблице инбокса сообщения категории «ГЕМ» получают заметный цветной бейдж «ГЕМ», выделяющий заявки в потоке. Сообщения категории «Прочее» показываются без бейджа, с нейтральным оформлением.

В панели просмотра сообщения (drawer) добавляется выпадающий список «Категория» для ручного переназначения. После смены категории список инбокса и счётчики обновляются.

Все новые элементы интерфейса, подписи и сообщения об ошибках — на русском языке, в стиле существующего раздела.

## Фича 7. Демо-данные и пересоздание базы

Новые поля категории и источника её определения добавляются в таблицу сообщений двумя путями:

- В свежей базе — через основную схему (`SCHEMA_SQL` в `bootstrap.js`), с последующим reseed демо-данных (`npm run seed:demo`).
- В уже существующей базе — через идемпотентный механизм добавления колонок (`COLUMN_MIGRATIONS` в `bootstrap.js`): при старте недостающие колонки дотягиваются `ALTER TABLE ADD COLUMN` с безопасным `DEFAULT`, без reseed и без потери данных. Поэтому оба новых поля обязаны иметь `DEFAULT` (категория по умолчанию — «Прочее», источник по умолчанию — «автоматически»).

Демо-данные проставляются так, чтобы в инбоксе сразу были видны и сообщения «ГЕМ» (в т. ч. со статусом «Новое»), и «Прочее» — фича демонстрируется без подключённого WhatsApp-коннектора. Категория в демо-данных задаётся согласованно с распознаванием (сообщения с упоминанием «@ГЕМ» — категории «ГЕМ», источник «автоматически»).

## Решения по уточняющим вопросам

- **Хранение справочника категорий и ключевых слов** — конфигурационный файл (Фича 3), а не таблица БД, несмотря на то что прочие справочники проекта (`statuses`, `categories`) лежат в SQLite. Причина: правка без миграций и reseed, отделение от логики распознавания. Сами поля категории на сообщении при этом хранятся в БД (см. ниже).
- **Пересчёт авто-категории при изменении конфигурации** — да, при старте приложения авто-категория переоценивается для сообщений с источником «автоматически»; «вручную» не трогаются (Фича 2).
- **Ключевые слова «ГЕМ» в MVP** — единственный стем «@гем» (Фича 3).

### Модель данных (ориентир для реализации)

В таблицу `wa_messages` добавляются две колонки (имена развязаны с категориями тикетов):

- категория сообщения — текстовый код категории, `NOT NULL DEFAULT 'other'` (значение по умолчанию — «Прочее»);
- источник определения — текстовый код, `NOT NULL DEFAULT 'auto'` со значениями `auto` / `manual`.

API использует коды категорий (например `problem` / `other`), а не русские названия; в запросе фильтра неизвестный код игнорируется (показываются все категории), по аналогии с обработкой статуса. Русские подписи («ГЕМ», «Прочее») и сообщения об ошибках живут на стороне отображения и в конфигурации категорий.

## Тестирование

- Юнит-тесты распознавания категории: формы упоминания «@ГЕМ» (разный регистр, хвост пунктуации, в составе фразы), отсутствие текста (только вложение), обычное сообщение без пометки, отсутствие ложного срабатывания (например, `user@гем.kz` или слово «гем» без `@`).
- Юнит-тест пересчёта при старте: после изменения конфигурации авто-категория сообщений с источником «авто» обновляется, а сообщения с источником «вручную» сохраняют категорию.
- Smoke-тесты API: фильтр списка сообщений по категории (в т. ч. в комбинации с фильтром по статусу), счётчики категорий в сводке, ручное переназначение категории и отказ при недопустимом значении, игнорирование неизвестного кода категории в фильтре.
