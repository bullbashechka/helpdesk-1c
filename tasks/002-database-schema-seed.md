# 002. Схема БД, справочники и демоданные

## Этап

Этап 2. База данных и серверная основа

## Цель

Реализовать SQLite-схему из семи таблиц, фиксированные справочники и первичное наполнение демонстрационными данными.

## Контекст из PRD

База данных состоит из клиентов, договоров, сотрудников, заявок, статусов, категорий и работ по заявке. Внешние ключи SQLite должны быть включены принудительно.

## Scope

- Подключить `better-sqlite3`.
- Создать модуль инициализации SQLite.
- Включить `PRAGMA foreign_keys = ON`.
- Создать таблицы: clients, contracts, employees, tickets, statuses, categories, work_logs.
- Задать связи между таблицами согласно PRD.
- Заполнить статусы: новая, в работе, ожидает клиента, выполнена, закрыта.
- Заполнить категории: консультация, доработка, ошибка, обновление.
- При первом запуске добавить несколько клиентов, договоров, сотрудников, заявок и записей о работах.
- Сделать инициализацию идемпотентной.

## Out of Scope

- REST endpoints.
- Интерфейс управления данными.
- Импорт данных из внешних источников.

## Requirements

- Удаление связанных записей должно блокироваться внешними ключами.
- Заявка ссылается на договор, категорию, статус и ответственного сотрудника.
- Работа по заявке ссылается на заявку и сотрудника.
- Дата создания заявки сохраняется автоматически на уровне приложения или БД.
- Демо-данные должны позволять проверить дашборд, списки, графики и отчёты без ручного ввода.

## Acceptance Criteria

- После первого запуска создан файл SQLite.
- Все семь таблиц существуют.
- В таблицах statuses и categories есть фиксированные значения из PRD.
- Повторный запуск не дублирует фиксированные справочники и демоданные.
- Попытка удалить клиента с договором, договор с заявкой, сотрудника с заявкой или заявку с работами завершается ошибкой внешнего ключа.
- В демо-данных есть минимум одна просроченная незакрытая заявка.

## Implementation Notes

Для фиксированных справочников использовать стабильные slug/code поля или уникальные названия, чтобы frontend и отчёты не зависели от случайных id.
