# 005. Дашборд заявок

## Этап

Этап 4. Основной workflow заявок

## Цель

Реализовать стартовый экран со сводкой по заявкам, графиками и последними заявками.

## Контекст из PRD

Дашборд должен показывать общую картину без перехода в списки: общее количество заявок, количество по статусам, количество просроченных, графики по статусам и категориям, список последних заявок.

## Scope

- Добавить backend endpoint или использовать существующие endpoints для получения агрегатов.
- Показать счётчик общего количества заявок.
- Показать количество заявок в каждом статусе.
- Показать количество просроченных заявок.
- Показать график распределения заявок по статусам.
- Показать график распределения заявок по категориям.
- Показать список последних заявок.
- Сделать переход из последней заявки в её карточку.

## Out of Scope

- Настраиваемые виджеты дашборда.
- Сложная аналитика и drill-down отчёты.
- Экспорт данных с дашборда.

## Requirements

- Просроченные считаются по правилу PRD: дедлайн прошёл и статус не «закрыта».
- Графики должны строиться по фактическим данным из БД.
- Последние заявки сортируются по дате создания от новых к старым.
- Дашборд должен работать на демонстрационных данных сразу после первого запуска.

## Acceptance Criteria

- На дашборде виден общий счётчик заявок.
- На дашборде видны счётчики по всем пяти статусам.
- На дашборде виден счётчик просроченных заявок.
- Есть минимум два графика: по статусам и по категориям.
- Список последних заявок содержит тему, клиента, статус, дату создания и дедлайн.
- Клик по последней заявке открывает карточку этой заявки.

## Implementation Notes

Если используется библиотека графиков, выбрать лёгкую и совместимую с Vite. Не добавлять серверную авторизацию ради дашборда.
