# 006. Список заявок, поиск и просроченные

## Этап

Этап 4. Основной workflow заявок

## Цель

Реализовать основной рабочий экран со списком заявок, поиском, подсветкой и фильтром просроченных.

## Контекст из PRD

Список заявок — основной рабочий экран. Таблица содержит тему, клиента, категорию, статус, приоритет, дату создания, дедлайн и исполнителя.

## Scope

- Реализовать страницу списка заявок.
- Вывести таблицу со всеми столбцами из PRD.
- Добавить строку простого поиска по теме и описанию.
- Добавить фильтр «просроченные».
- Визуально выделять просроченные незакрытые заявки.
- Добавить действие открытия карточки заявки.
- Добавить действие перехода к созданию новой заявки.
- Обновлять список после создания или редактирования заявки.

## Out of Scope

- Расширенные фильтры по клиенту, сотруднику или статусу.
- Массовые операции.
- Kanban-представление.

## Requirements

- Поиск ищет совпадения по теме и описанию.
- Фильтр просроченных показывает только заявки с прошедшим дедлайном и статусом не «закрыта».
- Заявки без дедлайна не считаются просроченными.
- Таблица должна оставаться читаемой на типичном рабочем экране.
- Данные клиента, категории, статуса и исполнителя показываются человекочитаемыми названиями.

## Acceptance Criteria

- Список отображает заявки из БД.
- Все столбцы из PRD присутствуют.
- Ввод текста в поиск ограничивает список подходящими заявками.
- Включение фильтра «просроченные» показывает только просроченные заявки.
- Просроченные строки визуально отличаются от обычных.
- Клик по заявке открывает её карточку.
- Кнопка создания открывает форму новой заявки.

Поиск можно выполнять на сервере через query-параметр, чтобы поведение списка и будущих отчётов не расходилось.
